# oxml-cli 0.0.14

Release preparation dated 2026-11-01. This file does not announce a
publication or authorize a tag.

## Highlights ⭐️

* **Bounded CLI and stdin input**: Cap file and stdin reads at 8 MiB using strict core parsing and XPath evaluation budgets.
* **Lockstep ecosystem integration**: Align package and fuzz harness metadata at `0.0.14` across the `oxml` suite.
* **Dual-lockfile security auditing and release parity**: Enforce `cargo audit --deny warnings` across both `Cargo.lock` and `fuzz/Cargo.lock` in CI, and retain automated GitHub Release generation with CycloneDX SBOMs, SHA-256 checksums, SLSA build provenance, and Scorecard pull-request SARIF configuration parity.

## Upgrade notes

Rust 1.89.0 or newer is required. All family packages share version 0.0.14, including unpublished
fuzz/conformance harnesses. The
harnesses remain non-publishable.
Inputs exceeding the documented application budgets return errors.

## Verification and release status

The fuzz policy permits NCSA only for libfuzzer-sys 0.4.13; it does not
extend the runtime license allowlist. Security CI checks both graphs.
Release tags must be annotated, signed by a key in
`.github/allowed_signers`, and use the subject `oxml-cli v0.0.14`.
The release workflow uses crates.io Trusted Publishing without a stored
token fallback. Configure this repository and `release.yml` on crates.io
before tagging; local signature fixtures do not verify that registration.

Release workflows wait for their exact family prerequisites before testing,
propagate publication failures and retain the dry-run-only laptop boundary.

Publish and index oxml and xmlschema before registry-only validation.
Local family-source overlays verify integration but do not prove that a
version exists on crates.io or that registry-only lockfiles can resolve.
Regenerate and verify registry locks after the prerequisites are indexed.

The final source commit must pass the repository gate and published PR
checks. Review artifact contents, checksums and signing configuration
before authorizing publication. The release page's change list and
checksums must come from actual metadata and artifacts, not placeholders.
